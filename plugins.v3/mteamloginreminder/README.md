# 馒头登录提醒

读取 M-Team（馒头）账号的**真实登录时间**，在临近掉号线之前提醒你去登录。

## 为什么需要它

M-Team 的账号删除规则是「未封存账号连续 **40 天**不登录将被删除」，而且站点公告明确写了：

> 登入指用瀏覽器存取網站網頁進行登入或存取，單純做種不算登入，**使用第三方工具間接存取也不算登入**

也就是说：**MoviePilot 的自动签到、用户数据采集都不算登录**，只有你自己用浏览器登录才算。所以自动化保号在这里是无效的，必须有人提醒。

## 提醒逻辑

- 以账号最近一次真实登录时间为**周期起点**，默认 **30 天**一个周期（可配置）
- 距上次登录达到「周期 − 提前天数」（默认 30 − 7 = **第 23 天**）后，**每天早上 8 点**提醒一次（时间可配置）
- **检测到新的登录记录** → 发送一条结束通知（含下一轮提醒日期），本轮不再提醒
- 新登录即开启下一个周期，如此循环
- 同一天只会提醒一次（定时任务本身每天执行一次，另有防重复保护）

## 通知文案

**每日提醒**（第 23 天起）：

> 【馒头登录提醒】该登录了
>
> **馒头**账号上次真实登录：**2026-09-16 14:16:03**，距今 **24** 天，距 30 天周期还剩 6 天。
>
> 站点规则：未封存账号连续 **40** 天不登录将被删除；自动签到/第三方工具访问**不算登入**，请用浏览器登录一次。

**检测到新登录**：

> 【馒头登录提醒】已恢复，不再通知
>
> 已检测到馒头账号的新登录记录：**2026-10-11 14:16:03**。
>
> 本轮提醒结束，**不再通知**。
>
> 下一个 30 天周期将于 **2026-11-03** 起再次提醒（提前 7 天）。

## 配置项

| 配置 | 说明 |
|---|---|
| 启用插件 | 开关，启用后每天定时检测 |
| 立即运行一次 | 保存后立即检测一轮，用于验证配置与通知渠道 |
| 发送通知 | 多选 MoviePilot 已启用的通知渠道，留空则只写日志 |
| 周期天数 | 默认 30 |
| 提前提醒天数 | 默认 7（即第 23 天开始提醒） |
| 每天提醒时间（小时） | 默认 8（即每天 8:00） |

## 数据来源

- 调用 M-Team 开放 API：POST https://api.m-team.cc/api/member/profile ，读取 memberStatus.lastLogin（真实登录）与 lastBrowse（最近浏览）
- ApiKey 自动从 MoviePilot 的站点配置读取（设定 → 站点 → 馒头 → ApiKey），无需在插件里重复填写
- 未在 MoviePilot 配置 M-Team 站点时会在插件日志中提示

## 说明

- 插件**不做**自动登录/签到，那是站点签到插件的职责；本插件只负责"提醒你本人去登录"
- 登录时间来自站点自己的记录，**读取不会污染它**（不像用户页上的「最近动向」会被任何请求刷新）
- 站点规则中封存账号的删除线是 90 天，未封存是 40 天，本插件默认按更严格的 30 天周期提醒，留足提前量

# MoviePilot 播放进度洗版插件

MoviePilot V2 插件：按媒体服务器（Emby / Jellyfin）上的**分集播放进度**决定订阅是否继续洗版。

洗版（best_version）的完成判定由宿主的「分集优先级」驱动：某集的 `episode_priority` 等于 100 即视为该集洗版完成、不再搜索更高版本；电影看 `current_priority`。插件读取播放进度，把已经看过的集写成 100，宿主的洗版流程自然跳过它们。

插件**只读**媒体服务器、**只写**订阅表：不删除文件、不下载、不触发整理、不动下载器。

本实现使用 V2 导入路径：`app.plugins` / `app.core.config` / `app.log` / `app.helper.mediaserver` / `app.helper.service`，订阅读写走 `app.db.subscribe_oper.SubscribeOper`。

## 工作原理

1. 每轮取「订阅中（state=R）且已开启洗版」的订阅，跳过已经全部完成的
2. 在媒体服务器上按名称 / 年份 / TMDB ID 匹配条目（名称相同 +4、年份相同 +2、TMDB 相同 +8，取最高分）
3. 读取每集的 `UserData`（Played / PlayedPercentage / PlaybackPositionTicks）并归一化成「是否已看 + 进度百分比」
4. 按判定方式判断某集是否算看过
5. 命中的集写入 `episode_priority[集号] = 100`，保留其它集既有优先级，并把 `current_priority` 重算为目标集范围内的最小值
6. 电影命中则写 `current_priority = 100`，整部停止洗版

三处与宿主口径对齐（改动时不要漏）：

- **整部优先级取目标集最小值**：宿主 `get_best_version_current_priority` 就是这么算的，只改分集而不更新它会让准入基线与实际分集状态不一致
- **空 map 先用 current_priority 回填**：订阅还没有分集优先级时，先用 `current_priority` 填满全部目标集再改；否则一旦写入非空 map，宿主的回退逻辑失效，未写入的集会被当成 0，反而放宽洗版准入
- **全集洗版要求全部命中**：`best_version_full` 的订阅由宿主按整部判断完成，只有目标集全部看过才写 100

## 安装

把本仓库配置为 MoviePilot V2 插件市场后，在插件市场中安装「播放进度洗版」。

仓库目录结构：

    plugins.v2/playbackbestversion/__init__.py
    package.v2.json
    icons/playbackbestversion.svg

V2 索引里该条目带 `"v3": false`，表示同一插件另有 V3 专用实现（本仓库 plugins.v3/ 下的 v3.0.0），V2 宿主不会看到 V3 版本，V3 宿主也不会回退使用本实现。

## 配置说明

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| 启用插件 | 关 | 开启后按检测间隔定时检查 |
| 媒体服务器 | 全部 | 多选，只列已启用的 Emby / Jellyfin；留空表示全部 |
| 统计哪些用户 | 服务器配置的用户 | 多个用英文逗号分隔；留空时用媒体服务器配置里绑定的用户 |
| 判定方式 | 播放进度达到阈值 | 见下节 |
| 进度阈值（%） | 90 | 仅「播放进度达到阈值」时生效，取值 1~100 |
| 检测间隔（分钟） | 30 | 最小 1 分钟 |
| 处理电视剧 | 开 | 按集写入分集优先级 |
| 处理电影 | 开 | 命中后整部停止洗版 |
| 试运行（只记日志） | 关 | 只把要写入的内容打进日志，不写库 |
| 发送通知 | 关 | 有实际写入时发送汇总通知 |
| 通知渠道 | 空 | 多选，取系统中已启用的通知渠道类型；留空不发送 |
| 立即运行一次 | 关 | 保存配置后约 3 秒执行一轮，跑完自动复位 |

## 判定方式

| 判定方式 | 命中条件 |
| --- | --- |
| 播放进度达到阈值 | `Played=True` 或 播放进度 ≥ 阈值（默认 90%） |
| 只要播放过 | `Played=True` 或 播放进度 > 0 |
| 标记为已看 | 仅 `Played=True` |

## 注意事项

- **只写不回滚**：停用或卸载插件不会把已经写入的 100 改回去；需要恢复洗版时手动修改订阅的分集优先级
- **先试运行**：打开「试运行（只记日志）」跑一轮，确认日志里「将写入」的内容符合预期后再正式启用
- **找不到条目就不写库**：媒体服务器上没有匹配的剧集 / 电影时，详情页状态显示「未找到条目」
- **多服务器按顺序尝试**：第一个匹配到条目的服务器生效，不会跨服务器合并；同一服务器上的多个用户会合并，取进度更高或已看的那份
- **详情页**：插件详情页展示最近一轮的汇总统计，以及每个订阅一行（订阅 / 类型 / 季 / 服务器 / 播放进度 / 跳过洗版 / 结果）

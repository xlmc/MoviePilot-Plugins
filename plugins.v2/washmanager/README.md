# MoviePilot 洗版管家插件

把「按播放进度停止洗版」「每集最多洗两次」「看完即删」三件事合成一个插件，三个功能各自独立开关，共用同一份媒体服务器读取与订阅写库逻辑。

本实现基于 V2 插件 API：`app.plugins` / `app.core.event` / `app.core.config` / `app.helper.mediaserver` / `app.helper.service` / `app.utils.http`，订阅读写走 `app.db.subscribe_oper.SubscribeOper`。

## 三个功能

| 功能 | 默认 | 作用 |
| --- | --- | --- |
| ① 进度洗版 | 开 | 已看过的剧集/电影不再继续洗版 |
| ② 两次上限 | 开 | 每集最多下载两次：首发只下本批最低档，只升级一次到本批最高档 |
| ③ 看完即删 | 关 | 清理已看完的内容：前移开始集数、删媒体文件/刮削文件/空目录/媒体服务器条目/整理记录 |

## 为什么需要

- 宿主的洗版（best_version）没有次数上限：只要某集的 `episode_priority` 还没到 100，每轮搜索到更高优先级的候选就会重新下载替换，同一集可能被「洗」很多次。
- 看完的内容留在媒体库里只占空间：宿主的缺失集判定又会让删掉的文件被重新下载。

这两个问题其实是同一件事的两端——**要不要继续洗版**，所以合成一个插件：进度决定「停止洗版」，次数决定「最多洗几次」，看完决定「删掉」。

## 工作原理

一次定时任务（默认每 30 分钟）里：

1. 从订阅库取「订阅中（state=R）」的订阅，按配置过滤电视剧/电影；
2. **只读一次媒体服务器**（Emby / Jellyfin），拿到每个目标条目的播放进度、媒体库路径与最后播放时间；
3. 先跑**进度洗版**：命中的集写 `episode_priority = 100`，电影写 `current_priority = 100`；
4. 再跑**看完即删**：把订阅的 `start_episode` 前移到「连续看完的最后一集 + 1」，然后按配置删除文件与条目；
5. **两次上限**不在这里，它在宿主的资源选择事件里按每集阶段收窄候选。

写库范围只有 `episode_priority` / `current_priority` / `start_episode` 三个字段，其它数据不动。

### 判定口径

| 判定方式 | 命中条件 |
| --- | --- |
| 播放进度达到阈值（默认） | 播放百分比 >= 阈值（默认 90%） |
| 只要播放过 | 播放百分比 > 0 |
| 标记为已看 | 媒体服务器标记为已看 |

### 两次上限的阶段

| 阶段 | 含义 | 本轮放行的候选 |
| --- | --- | --- |
| 0 | 该集还没有任何版本 | 本批优先级**最低**的那一档（首发不追高） |
| 1 | 该集已有首发版本 | 本批优先级**最高**的那一档（只升级一次） |
| 2 | 该集已升级完成 | 全部拦掉，并把该集写成 `episode_priority = 100` |

阶段不靠「选择时就记账」，而是每次用宿主自己维护的下载事实对账：电视剧看 `episode_priority[集号]`，电影看 `current_priority`。下载失败（宿主没写库）时阶段原地不动，下一轮仍按原阶段重试，不会被永久卡死。

进度洗版或看完即删写过的 `100`，在事件里直接当成阶段 2（已完成），所以不会被两次上限重新放行升级。

### 看完即删为什么要先改开始集数

宿主的缺失集窗口从 `start_episode` 开始算。删掉文件却不动 `start_episode`，宿主会认为这些集缺失并重新下载。所以清理前先把 `start_episode` 前移到「连续看完的最后一集 + 1」，落在窗口外的已删集不再被判定为缺失。只处理「连续看完」的一段，跳集观看不会把中间没看的集一起放弃。

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| 启用插件 | 关 | 开启后启动定时检测与资源选择事件 |
| 试运行（只记日志） | 开 | 只把将要做的动作写进日志，不写库、不删文件、不改候选 |
| 发送通知 | 关 | 每轮有动作时发通知 |
| 立即运行一次 | 关 | 保存配置后 3 秒执行一次，执行完自动关掉 |
| 媒体服务器 | 空 | 留空表示全部已启用的 Emby / Jellyfin |
| 统计哪些用户 | 空 | 留空表示服务器配置的用户，多个用英文逗号分隔 |
| 判定方式 | 播放进度达到阈值 | 见上方判定口径 |
| 进度阈值（%） | 90 | 仅「播放进度达到阈值」时生效 |
| 检测间隔（分钟） | 30 | 定时检测间隔 |
| 处理电视剧 / 处理电影 | 开 / 开 | 按类型过滤订阅 |
| 通知渠道 | 空 | 留空表示不发送通知 |
| 启用进度洗版 | 开 | ① 的总开关 |
| 启用两次上限 | 开 | ② 的总开关 |
| 首发只下最低档 | 开 | 关闭后阶段 0 也放行全部候选 |
| 升级后停止洗版 | 开 | 阶段 2 写 100 并拦掉后续候选；只对开启了洗版的订阅生效 |
| 启用看完即删 | 关 | ③ 的总开关 |
| 标记订阅 | 开 | 前移 `start_episode` |
| 延迟清理（天） | 0 | 最后播放距今不足该天数时跳过 |
| 删除媒体库文件 | 开 | 按媒体服务器条目的 Path 删除 |
| 删除媒体服务器条目 | 开 | 删除 Emby / Jellyfin 里的条目 |
| 删除刮削文件 | 开 | 元数据 / 图片 / 字幕（只删与媒体同名的） |
| 删除空目录 / 删除整理记录 | 开 / 开 | 清理后目录为空时删除；删除整理历史记录 |
| 删除下载目录源文件 | 关 | **会破坏做种**：MoviePilot 默认用硬链接整理，只删媒体库侧不释放空间，需要释放空间时再开启 |

## 插件接口

| 接口 | 说明 |
| --- | --- |
| `GET /run` | 立即执行一次检查，返回本轮执行摘要 |
| `GET /status` | 每订阅每集的阶段、首发优先级、升级目标与最近一轮处理摘要 |
| `GET /reset` | 清空两次上限的阶段记录（不动订阅表），下次搜索重新从「首发最低档」开始 |
| `GET /restore` | 把插件写过的 `100` 还原成写入前的优先级 |

## 注意事项

- **先试运行**：默认开启试运行，确认日志里「跳过洗版 / 已清理 / 保留 N 个」符合预期后再正式启用
- **删除源文件会破坏做种**：默认关闭，开启前确保对应种子已停止做种
- **只对洗版订阅收尾**：没开洗版的订阅靠「缺失集」触发重下，永久拦截会让删掉的文件再也下不回来，所以「升级后停止洗版」只对洗版订阅生效
- **整包资源不参与档位筛选**：候选既没有 `allowed_episodes` 也没有 `episode_list` 时原样放行，避免整包资源被误拦
- **写库范围最小**：只写 `episode_priority` / `current_priority` / `start_episode`
- **从旧插件迁移**：本插件由「播放进度洗版」「洗版两次」「看完即删」合并而来，旧插件的配置与状态**不会**自动继承，请在新插件里重新配置；旧插件请先卸载
- **模块导入期不启动任务、不连网、不连库**：定时任务在 `init_plugin` 里创建，保存配置后立即按新配置重新排程，不必重启宿主

## 安装

把本仓库配置为 MoviePilot V2 插件市场后，在插件市场中安装「洗版管家」。

仓库目录结构：

    plugins.v2/washmanager/__init__.py
    package.v2.json
    icons/washmanager.svg

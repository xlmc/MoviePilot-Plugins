# MoviePilot 看完即删插件

MoviePilot V2 插件：媒体服务器（Emby / Jellyfin）上**看过的集**自动清理——先让订阅不再把它当成缺失集，再删掉媒体库文件、刮削文件、空目录、媒体服务器条目与整理记录。

本实现基于 V2 接口：`app.plugins._PluginBase` / `app.core.config.settings` / `app.log.logger` / `app.helper.mediaserver.MediaServerHelper` / `app.helper.service.ServiceConfigHelper` / `app.utils.http.RequestUtils`，订阅读写走 `app.db.subscribe_oper.SubscribeOper`，整理记录走 `app.db.transferhistory_oper.TransferHistoryOper`。

本插件**独立实现**删除能力，不依赖仓库内其它插件：媒体服务器接口调用、刮削文件识别、空目录清理、整理记录清理全部自带。

## 为什么不能直接删

宿主的「缺失集」判定只看媒体服务器：普通订阅每轮用 `range(start_episode, total_episode + 1)` 与媒体服务器上实际存在的集求交集，缺一集就重新搜索下载。所以直接删文件会把订阅拖进「删了又下、下了又删」的死循环。

插件的做法是**先改订阅、再删文件**：

1. 电视剧把 `start_episode` 前移到「连续看完的最远一集 + 1」，已删的集落在缺失窗口之外，宿主不再把它算作缺失
2. 洗版订阅（best_version）额外把命中集的 `episode_priority` 写成 100（宿主口径：等于 100 即该集洗版完成、不再搜索更高版本），并重算 `current_priority`
3. 电影在洗版订阅下写 `current_priority = 100`
4. 全部看完时 `start_episode` 会越过 `total_episode`，缺失窗口为空，订阅正常完成并归档

## 工作原理

1. 每轮取「订阅中（state=R）」且还有目标集的订阅
2. 在媒体服务器上按名称 / 年份 / TMDB ID 匹配条目（名称相同 +4、年份相同 +2、TMDB 相同 +8，取最高分）
3. 读取每集的 `UserData`（Played / PlayedPercentage / PlaybackPositionTicks）归一化成「是否已看 + 进度百分比」
4. **从开始集数起逐集判断，遇到第一集没看完就停止**——跳集观看不会把中间没看的集一起放弃
5. 命中后按顺序清理：媒体服务器条目 → 媒体库文件 → 下载目录源文件（可选）→ 刮削文件 → 空目录 → 整理记录

## 安全设计

- **连续窗口**：只处理从开始集数起连续看完的一段，中间断档即停
- **路径校验**：路径层级少于 3 段、路径不存在或是目录时拒绝删除
- **刮削文件归属判定**：只删与媒体文件同名（媒体名后紧跟非字母数字）的刮削文件；同目录存在该集另一个版本（如 `.x265`）或同 stem 的其它媒体文件时保守保留
- **空目录只向上 3 层**，且只删真正为空的目录
- **延迟清理**：可设置「最后播放时间距今至少 N 天」才处理，防止误判
- **试运行**：只把将要执行的动作写进日志，不删文件、不删条目、不写订阅

## 安装

把本仓库配置为 MoviePilot V2 插件市场后，在插件市场中安装「看完即删」。

仓库目录结构：

    plugins.v2/watchedcleaner/__init__.py
    package.v2.json
    icons/watchedcleaner.svg

## 配置说明

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| 启用插件 | 关 | 开启后按检测间隔定时检查 |
| 媒体服务器 | 全部 | 多选，只列已启用的 Emby / Jellyfin；留空表示全部 |
| 统计哪些用户 | 服务器配置的用户 | 多个用英文逗号分隔；留空时用媒体服务器配置里绑定的用户 |
| 判定方式 | 播放进度达到阈值 | 见下节 |
| 进度阈值（%） | 90 | 仅「播放进度达到阈值」时生效，取值 1~100 |
| 检测间隔（分钟） | 30 | 最小 1 分钟 |
| 处理电视剧 | 开 | 按集前移开始集数（洗版订阅同时写分集优先级） |
| 处理电影 | 开 | 命中后清理整部 |
| 延迟清理（天） | 0 | 最后播放时间距今不足该天数时跳过，0 表示不延迟 |
| 标记订阅 | 开 | **关闭后删掉的文件会被宿主判成缺失并重新下载**，只在明确不需要该订阅时关闭 |
| 删除媒体库文件 | 开 | 删除媒体服务器条目里记录的路径 |
| 删除媒体服务器条目 | 开 | 删除 Emby / Jellyfin 中的条目，避免媒体库残留失效条目与海报 |
| 删除刮削文件 | 开 | 同名 .nfo / 图片 / 字幕与 `.trickplay` 目录 |
| 删除空目录 | 开 | 删除后向上清理空目录（最多 3 层） |
| 删除整理记录 | 开 | 删除与媒体库文件对应的转移记录，避免历史记录指向已不存在的文件 |
| 删除下载目录源文件 | 关 | **会破坏做种**；开启后按整理记录找到下载目录中的源文件一并删除，才能真正释放空间 |
| 通知渠道 | 空 | 多选，取系统中已启用的通知渠道类型；留空不发送 |
| 发送通知 | 关 | 有实际清理动作时发送汇总通知 |
| 试运行（只记日志） | 关 | 只记日志，不删除、不写库 |
| 立即运行一次 | 关 | 保存配置后约 3 秒执行一轮，跑完自动复位 |

## 判定方式

| 判定方式 | 命中条件 |
| --- | --- |
| 播放进度达到阈值 | `Played=True` 或 播放进度 ≥ 阈值（默认 90%） |
| 只要播放过 | `Played=True` 或 播放进度 > 0 |
| 标记为已看 | 仅 `Played=True` |

## 注意事项

- **硬链接与保种**：媒体库文件通常是下载目录源文件的硬链接，只删媒体库侧不释放空间；要释放空间必须开启「删除下载目录源文件」，代价是种子失效。空间与保种互斥
- **顺序追剧才安全**：连续窗口按集号推进，跳集观看时后面的集不会被处理（这是刻意的保守行为）
- **先试运行**：打开「试运行（只记日志）」跑一轮，确认日志里的目标符合预期后再正式启用
- **只前移不回退**：`start_episode` 只会向前推进；需要恢复时手动修改订阅的开始集数
- **多服务器按顺序尝试**：第一个匹配到条目的服务器生效，不会跨服务器合并；同一服务器上的多个用户会合并，取进度更高或已看的那份
- **详情页**：展示最近一轮的汇总统计，以及每个订阅一行（订阅 / 类型 / 季 / 服务器 / 播放进度 / 订阅变更 / 清理结果）

# MoviePilot 洗版两次插件

MoviePilot V2 插件：让订阅里的**每一集最多下载两次**——第一次只下本批候选里**优先级最低**的一档，第二次只升到**最终档**，之后不再洗版。

本实现使用 V2 导入路径：`app.plugins` / `app.core.event` / `app.log`，订阅读写走 `app.db.subscribe_oper.SubscribeOper`。功能与 V3 版本 v3.2.0 一致。

## 为什么需要

宿主的洗版（best_version）没有次数上限：只要某集的 `episode_priority` 还没到 100，每轮搜索到更高优先级的候选就会重新下载替换。于是同一集可能被「洗」很多次——先来个 1080p、再来个 4K、过几天又来个更高码率的 4K，每次都重下一遍。

本插件在宿主的**资源选择**环节介入，把「本批候选」按每集阶段收窄：

| 阶段 | 含义 | 本轮放行的候选 |
| --- | --- | --- |
| 0 | 该集还没有任何版本 | 本批优先级**最低**的那一档（首发不追高；订阅设了分辨率时只在该分辨率里取最低档） |
| 1 | 该集已有首发版本 | 只放行**最终档**：订阅设了特效/包含关键词时是本批最高档，否则是固定最终档（默认 100）；本批没有就全部拦掉 |
| 2 | 该集已升级完成 | 全部拦掉，并把该集写成 `episode_priority = 100` |

这样每集最多下载两次：首发一次、升到最终档一次。

## 最终档怎么定

「最终档」不是写死的 100，而是按订阅自己表达的意图来定：

| 订阅的情况 | 最终档 | 效果 |
| --- | --- | --- |
| 设了**特效**（例如杜比视界） | 本批候选里最高的一档 | 候选都带该特效，取其中最高的下完就收尾 |
| 设了**包含关键词**（例如 `CHD|FRDS`） | 本批候选里最高的一档 | 候选都被关键词命中，取其中最高的下完就收尾 |
| 两项都没设（只按规则组洗版） | 「最终档优先级」（默认 100） | 该档没出现就一直等 |

原因：宿主把「特效」和「包含关键词」都当**标题正则硬过滤**（`app/application/torrent/download.py:_text_filter_failure`，与 `quality` / `resolution` 并列），设了它们之后，进入插件视野的候选本身就已经是用户想要的那一类资源。此时再死等规则组首层（100）没有意义——那一层可能根本不在用户的筛选范围内。

反过来说，关键词足够精确（例如写死了某个压制组加某个特效）时，本批候选通常只剩一两个，第二次根本没有更高的档可升，插件自然就只下了一次。

## 工作原理

1. 监听 `ChainEventType.ResourceSelection`（宿主在排序与下载之前发出，允许插件替换候选列表）
2. 只处理**来源是订阅**的批次：`origin` 形如 `Subscribe|{json}`，从里面取订阅 ID；手动搜索、RSS 等其它来源一律放行
3. 用订阅的 `episode_priority`（电视剧按集）或 `current_priority`（电影按整部）判断每集当前阶段
4. 按阶段算出「本轮允许的优先级」，只保留优先级等于它的候选，其余从本批里剔除
5. 升级完成的集写 `episode_priority = 100` 并重算 `current_priority`，宿主此后不再为它搜索

## 阶段靠对账，不靠记账

插件**不在选择候选时推进阶段**——选择不等于下载成功。阶段每次都用宿主自己维护的下载事实对账：

- 电视剧：宿主下载成功后写 `subscribe.episode_priority[集号] = max(旧值, pri_order)`
- 电影：宿主下载成功后写 `subscribe.current_priority = max(pri_order)`

所以下载失败（宿主没写库）时阶段原地不动，下一轮仍按原阶段重试；不会被永久卡死。写 `100` 之前的旧值会存进插件状态，随时可以用 `/restore` 还原。

## 配置说明

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| 启用插件 | 关 | 开启后监听资源选择事件 |
| 试运行（只记日志） | 开 | 只把将要放行/拦截的候选写进日志，不改候选、不写库 |
| 处理电视剧 | 开 | 按集计算阶段 |
| 处理电影 | 开 | 按整部计算阶段 |
| 首发只下最低档 | 开 | 关闭后阶段 0 也放行全部候选（等于不限制首发） |
| 升级后停止洗版 | 开 | 阶段 2 写 `episode_priority = 100` 并拦掉后续候选；**只对开启了洗版的订阅生效** |
| 最终档优先级 | 100 | 只在订阅**没设**特效/包含关键词时生效：阶段 1 只放行优先级等于它的候选。规则组最高层没到这一档（例如首层只出 4K、订阅却限 1080p）时调低它，否则该集会一直等待 |

## 插件接口

| 接口 | 说明 |
| --- | --- |
| `GET /status` | 每订阅每集的阶段、首发优先级、升级目标与最近一轮处理摘要 |
| `POST /reset` | 清空插件状态（不动订阅表） |
| `POST /restore` | 把插件写过 `100` 的集还原成写之前的优先级 |

## 注意事项

- **只对洗版订阅收尾**：「升级后停止洗版」只在订阅开启了洗版时生效。没开洗版的订阅，宿主靠「缺失集」触发重下，永久拦截会让删掉的文件再也下不回来——这类订阅只做「首发最低档」，升级后一律放行
- **最终档由订阅决定**：订阅设了「特效」或「包含关键词」时，宿主对这两项都是标题正则硬过滤（`app/application/torrent/download.py:_text_filter_failure`），本批候选本来就只剩用户想要的那一类，此时最终档取本批最高的一档，下完即收尾——关键词足够精确时第二次往往无档可升，等于只下一次。
- **没做限定时的等待是刻意的**：订阅既没设特效也没设包含关键词时，阶段 1 只等固定最终档，本批没有就全部拦掉。若某剧永远没有该档资源，该集会一直停在首发画质——把「最终档优先级」调低，或关掉「升级后停止洗版」让宿主继续按常规洗版
- **整包资源不参与档位筛选**：候选既没有 `allowed_episodes` 也没有 `episode_list`（拿不到集数信息）时原样放行，避免整包资源被误拦
- **覆盖不到目标集的候选会被丢弃**：例如集号落在订阅「开始集数」之外的候选，即使优先级匹配也会被剔除
- **写库范围最小**：只写 `episode_priority` 与 `current_priority`，其它集原有优先级保留
- **先试运行**：默认开启试运行，确认日志里的「保留 N 个 / 优先级」符合预期后再正式启用

## 安装

把本仓库配置为 MoviePilot V2 插件市场后，在插件市场中安装「洗版两次」。

仓库目录结构：

    plugins.v2/washtwice/__init__.py
    package.v2.json
    icons/washtwice.svg
